# Attack, Detection, and Response Evidence

This directory contains visual evidence from controlled cybersecurity attack, detection, investigation, and response exercises performed within the isolated cybersecurity homelab.

## Purpose

The objective of this directory is to demonstrate complete security workflows rather than isolated tool usage.

Exercises documented here should progressively demonstrate:

`Attack → Telemetry → Detection → Investigation → Response → Verification → Documentation`

## Lab Architecture

Controlled security testing may involve:

- `LAB-KALI-01` — REDNET — `10.10.10.10`
- `LAB-WIN-01` — CORPNET — `10.10.20.20`
- `LAB-UBUNTU-01` — SERVERNET — `10.10.30.30`
- `LAB-SIEM-01` — SOCNET — `10.10.40.10`
- `LAB-FW-01` — OPNsense firewall and segmentation gateway

Testing must remain within the authorized homelab environment.

## Evidence Standard

Strong attack-and-detection evidence should demonstrate multiple stages of the security lifecycle.

Where practical, evidence should include:

1. Controlled activity performed from the authorized source system
2. Endpoint or network telemetry generated by the activity
3. Detection by the monitoring platform
4. Investigation using CLI and/or Wazuh Dashboard
5. Identification of relevant indicators
6. MITRE ATT&CK mapping where applicable
7. Defensive response or remediation
8. Verification that the environment returned to the intended state

## Recommended Filenames

Use descriptive filenames such as:

`kali-nmap-reconnaissance.png`

`wazuh-recon-detection.png`

`suspicious-powershell-execution.png`

`wazuh-powershell-detection.png`

`linux-ssh-failed-authentication.png`

`wazuh-ssh-investigation.png`

`suricata-network-alert.png`

`incident-containment-verification.png`

Avoid generic filenames such as:

`Screenshot1.png`

`Screenshot2.png`

`image.png`

## Screenshot Evidence Rules

Screenshots should capture only information necessary to prove the security milestone.

Before publication, every screenshot must be reviewed for:

- Passwords
- Credentials
- Authentication tokens
- API keys
- Private keys
- Personal information
- Sensitive configuration data
- Unnecessary command history
- Other confidential information

Screenshots containing real credentials or secrets must not be committed.

## Controlled Testing

All attack simulations documented in this repository are performed against systems intentionally deployed within the isolated cybersecurity homelab for authorized educational and defensive-security testing.

Production systems, third-party infrastructure, and systems without explicit authorization are outside the scope of this project.
